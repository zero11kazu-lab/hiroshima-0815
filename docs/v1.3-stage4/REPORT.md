## 旧版との対応と原因

保存済みV1.0 `source-3ecb6ad.tar` 内の `src/npc.js` を読み、現行の外観分類と照合した。

|既存カテゴリ|旧版の分類割合|今回の人型での表現|
|---|---:|---|
|BURN_FULL|非倒臥の対象者30％|上衣の大部分を失い、広い赤褐色の火傷・煤|
|BURN_PARTIAL|同30％|上衣をほぼ失い、正常な肌と部分的な火傷が混在|
|CLOTH_HALF|同40％|片側の上衣・片袖を中心に残し、部分的な火傷|
|CHARRED|倒臥・死亡カテゴリ37.5％|炭化系の暗い肌・衣服、灰色の色ムラ|
|BURN_UPPER|同37.5％|上半身の焼損と火傷|
|BURN_FULL|同25％|広い火傷と焼損|

値はゲームの外見分類であり、実際の被爆者の負傷・死亡割合ではない。`hash10(index+816)` と閾値、子どものCLOTHED、マサミの軽度状態、M2男性の固定外見、M3負傷者のCLOTH_HALFを維持。`NPCVisuals.appearance()` とNPCの生死・行動処理は変更していない。

第3段階では、分類は残っていたが、BURN_PARTIALにも小さな破れ用形状を使い、上衣が多く残っていた。肌色も茶色に寄り、遠距離LODの胴は通常の布地UVのままだった。今回、分類結果を欠損形状・肌テクスチャ・遠距離表示の全てへ接続した。

## 人物の外見

- 一般NPCと重要NPCに「覆われた上衣」「半分程度の上衣」「ほぼ失った上衣」を共有geometryで設定。男性上衣の布面積は、通常相当を基準に半欠損で約52％、大欠損で約18％。袖・前腕も同様に残存量を切り替える。
- 残った布の下に人体を置き、同じ関節行列で描画。色変更だけではなく、布の三角形を欠損させる。皮膚と布を径方向に離し、端面にも6mmの間隔を設けて重なりを避ける。衣服だけの独立した浮遊メッシュ・物理処理は作らない。
- 肌は赤褐色・通常肌・煤をゆるやかに混合し、広範囲／部分的な火傷を区別。8系統のアトラス内で異なる模様を使う。炭化系は真っ黒一色にせず暗い茶・灰のムラを加える。
- CHARREDは従来と同じDOWN / DEAD / CHILD_DEADの判定範囲だけ。歩行者へ割り当てず、全死亡者を一律に炭化させない。生死フラグは変更しない。特にM2男性は帰還時も同じ外観を保つ。
- 子どもはCLOTHEDを維持。成人女性の上衣大欠損には簡素な内側の胸布を残す。過度な露出、流血、人体切断等は追加しない。
- 遠距離モデルにも肌・布の範囲を設定し、遠景だけ無傷に戻る状態を解消。

### 一雄・マサミ

一雄は被爆直後に肩・袖・胸元／裾の一部が破れ、肌に控えめな火傷が出る。被爆前のgeometry、顔、体格、関節・歩行・走行・ルート・衝突判定を維持する。被爆後だけ衣服geometryとmaterialを切り替え、RESETで元に戻す。

マサミは第3段階の女性用上衣・藍色のもんぺを保ち、肩・袖・前腕の傷み、煤、肌の部分的な火傷を追加。顔・髪・体格と既存アニメーションは維持し、探索時の14m表示制限も変更しない。

## 増員・地理

- 元29人 = 一般23人＋マサミ・重要NPC6人。一雄はNPC数に含まない。
- まず6人追加の35人で60秒相当の移動シミュレーションを実施。全追加者が33〜40m移動し、初期経路と投下後の在籍を確認。
- 東側をさらに2人追加して最終 **37人 = 一般31人＋重要6人**。追加8人は **東6人／西2人（75％／25％）**。
- 東西は既存 `placementSide()` と同じく御幸橋のX=50を基準に、地理的な東を+Xとする。画面の左右では判定しない。
- 東側は既存X=86の南北生活道路4区間、東側商店街横道（Z=-37）、橋東詰の先（X=68〜80、Z=38）。西側は北のX=-26の生活道路と南のX=2の生活道路。全て既存道路上で、建物・道路・川・橋を移動・削除していない。
- 狭い橋の上に新しい往復経路は追加しない。東詰の先に置いて既存の橋通行を守る。
- 新規IDを既存29人の後へ追記。既存29人のデータ全体をハッシュ照合し、配置・経路・会話・外見用indexを維持。新しいNPCへ既存の一般会話を再利用し、ミッション用フラグを引き継がせない。
- 投下後は既存の行動状態割当を使用。追加者は検索／歩行／座位／倒臥等に分かれ、全員が一斉に消えない。追加した東側2人は旧分類により炭化系の倒臥外観となる。

人数・配置は `data/npc_expansion_v13.json` で管理。歴史的な道路データ上での創作市民配置であり、その位置に実在人物がいたという再現ではない。

開始時の固定分は東8人・西28人、これにランダム配置のマサミ1人を加える。今回の検証サンプルは開始時東8／西29、被爆後はミッション配置で東12／西25。マサミ・ミッション配置や歩行に応じて全体の東西人数は変動する。追加分の6／2は固定。

## 負荷と最適化

形状・素材共有、InstancedMesh、稼働slotの詰め替え、18mからの一般NPC LOD、画面外の不要な関節更新停止、既存の距離別AI更新とA*予算を維持。NPCを増やしても人数に比例する高精細な常時描画にはしない。

CPU側の描画提出構成（影を含む、GPU実測ではない）:

|条件|第3段階29人|今回35人|今回37人|
|---|---:|---:|---:|
|開始地点 バッチ／三角形|28 / 8,630|29 / 8,894|29 / 9,110|
|全員近接の合成条件|46 / 42,860|46 / 49,868|46 / 52,200|
|全員遠方の合成条件|7 / 5,916|8 / 7,140|8 / 7,548|

同じデスクトップ・stub環境で20秒相当のNPC更新を単発計測すると、旧29人約502ms、新外見29人約513ms、35人約509ms、37人約529msだった。計測ぶれを含み、iPhoneのFPSや応答時間を表す値ではない。

一般NPC atlasは引き続き512×512の1枚・CPU画素1MiB。増員で個人別textureを増やさない。一雄の追加被爆後atlasは256×256・CPU画素256KiBで、元の共有画像を書き換えずにキャッシュする。NPC描画用geometry／instance配列の比較は [memory.json](memory.json) に記録。GPU／Safariの実メモリ測定ではない。実機が未確認のため40人への増員は行っていない。

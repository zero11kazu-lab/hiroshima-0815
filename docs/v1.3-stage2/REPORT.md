顔輪郭・顎・鼻・髪型、肩幅と身長を役割ごとに固定。衣服の損傷・煤・軽い火傷は同一geometryとpost atlasで表現する。M2の死亡時にも同じgeometry・paletteを保持し、姿勢と呼吸停止だけが変わる。

一雄の剛体関節リグ・歩行・会話方式を再利用。待機・歩行・会話・被爆時の傾き、負傷した座位、支援歩行、死亡時の静止へ接続。状態変化は約0.45秒補間。M3は身体を前に傾け、腕を進行方向へ伸ばす。既存の追従経路・移動速度・距離制限は不変であり、厳密な手の接触を保証するIKは追加していない。

## エンディング

フィールドと同じマサミのリグを室内用materialで複製。Aでは横臥・顔色と髪の衰弱・呼吸停止、Bでは正座して看取り・上体を曲げて悲しむ。Bの足位置は畳の高さに合わせ、悲嘆でも足を動かさない。室内material変更はフィールドへ伝播しない。

一雄の完成済みモデル・Aの正座／悲嘆・Bの横臥は維持。A/B抽選、会話データ、固定独白、各シーンの順番・時間、慰霊碑・完・タイトル復帰・音声処理は変更していない。

## 軽量化

- 6人の部品を共有geometryごとにInstancedMeshへまとめ、活動中のslotだけを詰めて送信。非表示人物を別オブジェクトとして描画しない。
- 近距離22m未満は関節モデル、遠距離は共有の簡略形状。マサミの被爆後14m制限とM3後の解放条件は維持。
- 画面外と遠距離では不要な関節更新を止める。既存NPC更新ループを使用し、新しいイベント・RAF・音声・ライトを作らない。
- 共通512×256 atlasを通常／被爆後／室内／衰弱に必要時生成。4枚全部でCPU pixel配列2MiB、GPUミップ込み概算2.67MiB。4K素材・外部モデル取得不要。
- 6人全員近距離の合成シーン: 22有効batch、16,176三角形。全員遠距離: 3有効batch、1,152三角形。旧NPCの5batchは一般NPCと既存影用として残す。通常プレイで6人同時に近接するとは限らない。
- 候補となるgeometry batchは計28。これはCPUでの構造計測であり、GPU draw calls・実測FPSを意味しない。

## 検証

`python build.py`、`git diff --check`、以下のNodeテストを実行。

1. `tests/important-people-v13.cjs`: 実際のThree.js geometry/UV/index/行列、成人・子どもの頭身、共有atlas shaderの差込と属性、近遠LOD、6人以外の旧描画、20回RESET、被爆前12回会話、M1→M2完了、M3前のマサミ非表示、M2同一性、子どもの頭部が梁より上、A/B室内と全ステージの完到達を確認。
2. `tests/kazuo-model-v13.cjs`: 一雄の既存関節とカメラ中心、火災・煙ダメージ、M3実歩行支援→完了→マサミ解放、両エンディングとRESETを確認。
3. `tests/kazuo-return-v13.cjs`: A/Bのタイトル復帰→STARTで同一の一雄モデルを再利用し新規状態に戻ることを確認。
4. `tests/camera-follow-v12.cjs`: 縦横viewport、回転、障害物回避・復帰、チェックポイント等の既存カメラ数値テストを確認。
5. 第1段階のsrc/data/assetsと比較し、既存ファイルの変更は `src/npc.js` と `src/ending.js` の表示接続だけ。その他53ファイルは同一。

経路テストの自動操縦はランダムな経路でNPC付近に詰まる場合があった。ゲーム処理を変更せず、回帰用M3候補 `v12-m3-EWW-07` を選ぶseedと、次区間が通行可能なら近い中間点を飛ばすテストドライバーに調整。全候補の手動通しプレイ成功を主張しない。

NodeテストはDOM/Canvas/WebGLRendererをstub化した数値・状態テストであり、ブラウザーの描画確認ではない。Blender/Cyclesで実際のゲームgeometry・UV・姿勢をオフライン描画し、投下前後・A/B・支援姿勢を目視確認。これはゲーム画面のスクリーンショットではない。

本環境ではSites指定のブラウザー操作ツールが利用できず、同Skillに従いブラウザーQAを実施していない。iPhone Safari実機、タップ・音声、実WebGL shader compile、実測FPS／メモリ、全候補の手動探索は未確認。既存V1.3 URLで実機確認が必要。

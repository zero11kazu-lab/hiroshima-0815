## マサミ

- 生成り・くすんだ薄茶の女性用上衣、藍色のもんぺ。斜めの襟、ゆとりのある袖、絞った足首、上衣の表面に浅い布の起伏を追加。一雄の帽子・緑系作業服・胸ポケットとは配色と形が異なる。
- 1945年前後の簡素な女性上衣・もんぺを参考にした創作衣装。特定の実在人物の衣服や史料写真の正確な復元とは扱わない。
- 第2段階の頭部・髪geometry、身長・体格scaleをハッシュ／数値で照合。顔、髪型、関節位置、既存アニメーションを維持。姿勢や論理位置を衣服に合わせて変更しない。
- 被爆後は上衣の肩・裾と袖の一部の三角形を実際に除去し、欠けた布端を作る。袖の下には控えめな皮膚、胴体には内側の上衣を残し、過度な露出を避ける。衣服の煤・焦げ・灰、従来の火傷用肌テクスチャも適用。
- 通常／損傷geometryを事前に共有しておき、8:15前後の既存WorldStateから表示slotだけを切り替える。人を複製・再配置しない。被爆後は服の色も暗く抑え、従来の14m表示制限とM3完了後の解放を維持。
- 通常時2,430三角形。30日後の室内は新しい通常衣装に既存の室内／衰弱用materialを使用。Aの横臥、Bの正座・看取り・悲嘆、顔色と呼吸停止へ接続。`ending.js` 自体は第2段階と同一。

## 一般NPC

既存23人を人型化し、重要NPC6人を含む総数29人を維持。NPCManagerを増やさず、第2段階のInstancedMesh描画器を拡張する。一雄のモデルは変更していない。

基本8系統:

1. 男性作業着
2. シャツとズボン
3. 高齢男性（灰髪、やや前傾）
4. 女性上衣ともんぺ
5. 着物風の合わせ襟・帯を持つ上衣と脚衣
6. 高齢女性（灰髪、やや前傾）
7. 子ども（短い四肢と胴、相対的に大きい頭）
8. 学生服と簡素な帽子

各IDへ身長・幅・衣装系統を固定割当。外見決定でゲーム用乱数を新たに抽選せず、途中で外見を入れ替えない。成人は約6.2〜6.5頭身、子どもは約5.3頭身。顔・耳・鼻・目・口、肩・肘・膝・足首を軽量な共有geometryで表現。

近距離通常時は **1,136〜1,184三角形**、衣服損傷時も **最大1,372三角形**。一般NPCの旧ブロック・球頭・帽子・裙の4描画batchはcountを0にし、二重描画しない。元の色データは既存の被害外観分類との互換性のため保持。

[8系統の通常モデル](crowd.webp) ／ [損傷・座位・横臥](damage.webp)

## 動作・被害状態

一雄の剛体関節・歩行／会話関数を再利用。左右反対の腕脚、膝・肘、待機・会話のわずかな呼吸と頭の動きを維持。高齢者の前傾、被爆後の弱い歩行、座り込み、仰臥、死亡時の静止を見た目だけで表現。

既存 `NPCVisuals.appearance()` を完全維持し、PRE / CLOTHED / CLOTH_HALF / BURN_PARTIAL / BURN_FULL / BURN_UPPER / CHARRED を既存の条件・割合で選ぶ。新しいatlasの行と、軽度／大きな破れのgeometryへその結果を渡す。立位と横臥で異なる姿勢を使い、CHARREDが選ばれる条件や子どものCLOTHEDルールも変えない。

NPCの論理位置、移動経路・速度、会話範囲、衝突判定、死亡フラグを描画処理から変更しない。新しいSkinnedMesh、IK、物理処理、更新ループ、ライト・音声は追加しない。

## 軽量化と負荷比較

- 一般NPC用は512×512 RGBA atlas **1枚**（CPU画素1MiB、GPUミップ込み概算1.33MiB）。8系統×7状態を同一atlasに収め、状態別textureの大量生成を避ける。
- geometry・materialを共有し、稼働slotだけを既存InstancedMeshへ詰める。未使用の損傷variantは描画しない。
- 一般NPCは18mから共有の簡略形状。重要NPCの22m、被爆後マサミの14mは維持。遠距離でも座位・横臥を区別する。
- 画面外・遠距離は不要な関節アニメーションを止める。既存のNPC距離別更新頻度を維持。旧ブロックの行列生成・GPU更新を省略。

同じ論理配置・距離条件でCPU側のシーン提出構成を比較（影batch込み）:

|条件|第2段階 バッチ／三角形|第3段階 バッチ／三角形|
|---|---:|---:|
|開始地点|19 / 13,670|28 / 8,438|
|29人を全員近接させた合成条件|27 / 26,384|46 / 42,860|
|29人を全員遠方へ置いた合成条件|8 / 11,360|7 / 5,916|

開始地点では提出三角形が減る一方、描画バッチは増える。全員近接時は形状もバッチも増える。遠距離ではLODにより減少する。旧方式の三角形数にはゼロscaleのslotも含む。これはGPU実測draw calls・FPSの測定ではなく、iPhoneで劣化がないことの証明にはならない。人数増加は行わず、実機で密集・火災シーンの確認が必要。

# HIROSHIMA 08:15 — 試作10 改修版

公開URLまたは `dist/index.html` を開き、開始ボタンをタップしてください。3D・コード・音楽・効果音生成を同梱した単一HTMLです。遊ぶ人のnpm、ビルド、外部音源は不要です。iPhoneはSafariでURLを開く方法を推奨します。

## 今回の進行

投下前の街歩き・会話・届け物・妻の聞き込み、8:13の航空機音、8:15の閃光・音の遅れ・爆風・暗転・意識回復を維持しています。投下前に警告やカウントダウンを出しません。

投下後は「周囲を確かめ、人の声を探す」から始まります。マサミは意識回復時に描画・接触・会話対象から外し、二つの依頼を終えるまでは発見できません。投下前に会っていた場合も同じです。

1. **子どもを探して**：母親に話し「探す」を選ぶ。西の路地の傾いた屋根を目印に、瓦礫の下の子どもを探します。助けようとする短い会話と動作の後、応答がなくなります。母親のもとへ戻り、報告を最後まで進めると完了します。
2. **水をくれ**：ミッション1の完了後、橋の北側の男性から受けられます。西の道の水音を探し、壊れた消火栓で「水を汲む」→「はい」。戻った男性には「確認する」で反応を確かめます。水を渡す成功演出にはせず、この確認を最後まで進めて完了します。
3. **マサミを探す**：両ミッション完了かつ未配置の場合だけ、現在のプレイヤーから遠く、安全で到達できる地点へマサミを配置します。以後、NPCへの聞き込みが使えます。妻の正確な位置マーカー・矢印は出しません。

登場人物・会話・二つの出来事はゲーム用のフィクションで、実在人物の証言ではありません。人物の損傷・血液等の詳細表現はありません。男性の死亡は距離/進行条件による創作イベントで、水を飲ませた結果として描いていません。

## 操作の修正

- 左下スティックで移動。離すと停止。右側ドラッグで手動カメラ。
- **右下「走る · 押す間」を押し続ける**と走ります。左手のスティックと右手のボタンを同時使用してください。
- 歩行 `PLAYER_WALK_SPEED=2.9m/s`、走行 `PLAYER_RUN_SPEED=歩行×1.9`。熱・煙・瓦礫による減速は両方に作用します。スタミナ0では走れず、歩行は続けられます。
- Pointer EventsとSafari用Touch Eventsで押下/終了/キャンセルを処理。走行ボタンの操作で左スティックを消しません。
- 投下後の移動は最大1/30秒の小刻みな更新にし、15/30/60fpsで同じ移動速度を保ちます。大きい一歩で薄い壁を抜けない設計です。
- 「話す」と会話ウィンドウは、8:15演出後も不透明度を戻します。以前は `hidden=false` にしても `opacity=0` が残っていました。投下後の接近判定は約3.1m。
- DOWNや死亡状態には「確認する」、子どもには進行に応じ「助ける」、消火栓には「水を汲む」を表示します。

## サバイバルの強化

熱・火炎・煙・体力・スタミナは、ミッションや会話中も有効です。必須地点は火災中心を避けて配置し、各地点間の安全な迂回経路を生成時に検査します。

| 状態 | 設定 |
| --- | --- |
| 熱の上昇 | 応答時間0.85秒。強火災の縁で約3秒で95程度まで上がる試験を確認 |
| 熱60〜79 | 体力 約3/秒低下 |
| 熱80〜94 | 体力 約10/秒低下 |
| 熱95〜100 | 体力 約18/秒低下 |
| 炎接触 | 追加で `6 + 接触量×22` /秒。短時間の退避は可能だが、強い接触を続けると約4秒で体力0となる試験を確認 |
| 退避 | 熱は毎秒4ずつ低下。蓄積熱が高い間は影響が残る |
| 高熱時 | 減速、スタミナ消費増大、回復抑制、呼吸音、控えめな熱の画面効果 |

数値はゲーム用の厳しい仮設定です。熱の物理的再現値ではありません。火災・煙・瓦礫、建物のDESTROYED、緑葉を残さない樹木切替は維持しています。放射線、空腹/水分、戦闘、クラフト、治療や詳細な人体損傷は追加していません。

## 音量と音の種類

`AMBIENT_MIX` に環境音の音量を集約。BGMゲインは0.55→0.8、航空機の基本ゲインは0.012→0.075へ変更し、スマートフォンで聞き取りやすい倍音を増やしました。左から頭上付近、右へ進むパンと距離感の音量変化を維持します。この8:13の音は史実確定の聴取体験ではなく、演出的環境音です。

投下前は風・街の声風の環境音・鳥・プレイヤー/近傍NPCの足音。投下後は火災・風・遠い崩落音・声風の環境音・呼吸・消火栓付近の水音。声は言葉のない生成音で、録音した日本語台詞ではありません。航空機と投下前BGMは閃光時に停止し、投下後には戻しません。

マスターにコンプレッサーを追加し、単純な最大音量化によるクリップを避けます。音源はすべて独自生成。♪ボタンでON/OFF。iPhone実機の聞こえ方は未確認のため、正式な音源・最終ミックスは差し替え可能な構造です。

## ミッション・状態・チェックポイント

既存 `MissionController` の会話選択肢、目的表示、NPC目印、スナップショットAPIを共有し、長い投下後進行だけ `PostMissionController` へ分離しました。定義データは id / title / giverNpcId / targetNpcId / state を持ちます。

- MISSION_1_INACTIVE → ACTIVE → CHILD_FOUND → RETURN_TO_MOTHER → COMPLETED
- MISSION_2_INACTIVE → ACTIVE → WATER_COLLECTED → RETURN → COMPLETED
- FIND_MASAMI_ACTIVE

ミッション2は1の完了前に受注できず、水取得や妻の再配置も順番の条件を満たさない限り発生しません。子どもはCHILD_TRAPPED→CHILD_DEAD、男性はMALE_WAITING→MALE_DEAD。男性は依頼後に一定距離離れると状態変更し、水を汲んだ時点でも帰還時の状態を保証します。

マサミの再配置条件は `mission1Completed && mission2Completed && !masamiRepositioned`。現在地から45m以上の候補を遠い順に調べ、火災中心/高熱/煙/壁/他人を避け、経路を確認します。今回の確認では約100m以上離れた場所を選び、再配置は一度のみでした。聞き込みは再配置先に合わせた相対方向・距離で変化します。

チェックポイントは意識回復後、依頼1開始/完了、依頼2開始/完了。体力0では静かに暗転し「直近の地点から再開」で戻れます。体力・熱・スタミナと人物位置を戻し、完了済みミッションは維持します。水取得後の帰還中に失敗した場合は、水の依頼開始から再挑戦します。永続セーブはなく、ページ再読み込みでは初期化します。

母親と報告先には控えめな目印を使用します。子ども・消火栓は方角と景観・水音で探す方式です。妻には目印を使いません。

## 開発用確認

`?debug=1` を付けて開き、開始後INFO。PRE / 08:15 EVENT / POST / 連続ミッション、HEAT 50 / 90、FIRE DAMAGE、SMOKE、GAME OVERを直接テストできます。連続ミッションのボタンは投下後開始へ進め、ミッション順序自体は省略しません。通常URLにはこのパネルを出しません。

`window.__game.getPostMissions()` / `getMissions()` / `getAmbient()` / `getSurvival()` / `getEvent()` / `getAftermath()` が検証APIです。開発者用ビルドは `python build.py`。検証結果・実機の限界は `VERIFICATION.md` に記載しています。

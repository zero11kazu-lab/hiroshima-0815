# V1.4 橋の出入口のカメラ修正

## 原因と変更範囲

御幸橋は X=36〜64、Z=35〜41。左右の欄干・柱は描画負荷削減のため材質別に結合されている。従来のカメラは結合後メッシュ全体のAABBを障害物として使用しており、左右の欄干の間の通路まで障害物として扱っていた。プレイヤーがこの箱の内側にいると一時的な透過、境界の外側に出ると衝突回避の急な仰角上昇となり、ほぼ上空視点へ跳ねた。

道路と橋の高さを切り替えるカメラモードはなく、再現中のプレイヤーY=.08／注視点Y=1.15は連続。主因は地面高さではなく障害物の過大な範囲。

`src/camera.js` のみ実行コードを変更。カメラ専用に、連結していない形状を分けた包囲箱をキャッシュする。UV・法線のシームを位置で照合し、三角形の連結成分を計算。ローカル形状の計算はWeakMapでジオメトリ単位に再利用し、ワールド座標への変換は障害物キャッシュ更新時だけ行う。毎フレームは従来の近傍選別とスラブ交差判定を部材の箱に適用する。

橋固有の除外条件を追加せず、描画を結合した建物・小物にも同じ方法を適用。カメラ半径.25、建物回避、補間、手動操作、lookAt、FOVと縦横対応の処理は維持。描画ジオメトリ、移動用コライダー、街並み、NPC、物語とUIは変更しない。

## 性能・確認の限界

描画部品・三角形・マテリアル・テクスチャの追加は0。一般NPC37人を維持。投下前のカメラ障害物475メッシュに対して部材箱5,037個。CPUのみの同条件5,000更新×3測定中央値は旧0.0514ms/更新、新0.1830ms/更新（約+0.132ms）。初期化全体は旧3.238秒、新3.455秒。この値はNode上の計測で、iPhone FPSやGPU性能の実測ではない。結果には測定環境と負荷による変動がある。

テストは実際のThree.jsシーンとゲームコードを実行するが、DOMとWebGLRendererはスタブ。ブラウザ描画・タッチ操作・iPhone実機の縦横回転・長時間安定性・実機FPS/メモリは未確認。比較図も画面画像ではなく実際のカメラ計算ログ。
